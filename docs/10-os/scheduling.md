# 用户态与内核态、系统调用、CPU 调度

> 频率：★☆☆ · 近两年出现在：字节（进程/线程/协程、内核态与用户态）、腾讯（原码反码补码、键盘输入到屏幕显示） · 参考：[JavaGuide](https://javaguide.cn/cs-basics/operating-system/operating-system-basic-questions-01.html)

## 一句话答案

**系统调用**是用户程序请求内核服务的接口（读写文件、网络、创建进程、申请内存）：执行特殊指令（x86-64 的 `syscall`）陷入内核态，内核按系统调用号执行对应函数，完成后返回用户态。**CPU 调度**决定下一个运行哪个线程：常见算法有先来先服务、短作业优先、时间片轮转、优先级、多级反馈队列；Linux 普通进程用 **CFS**（完全公平调度，按虚拟运行时间最小的先跑），6.6 内核起换成 **EEVDF**。

## 展开（1–2 分钟能讲完）

**系统调用的过程**：

1. 用户程序调用 C 库函数（如 `read`），库函数把系统调用号放进寄存器（`rax`），参数放进其他寄存器。
2. 执行 `syscall` 指令：CPU 切换到内核态，跳转到内核的入口。
3. 内核保存用户态寄存器，按调用号查**系统调用表**，执行 `sys_read`。
4. 完成后把返回值放进寄存器，执行 `sysret` 回到用户态。

开销在于特权级切换、保存恢复寄存器、可能的缓存和 TLB 污染（为了防 Meltdown 的页表隔离 KPTI 还增加了开销）。所以要减少系统调用次数：批量读写、用缓冲区、零拷贝、`io_uring`。

**调度算法**：

| 算法 | 特点 |
|---|---|
| 先来先服务 | 简单，短任务可能被长任务拖很久 |
| 短作业优先 | 平均等待时间最短，但要预知执行时间，长任务可能饿死 |
| 时间片轮转 | 每个任务轮流跑一个时间片，响应快，适合交互 |
| 优先级 | 高优先级先跑，低优先级可能饿死，用「老化」逐渐提高等待久的任务的优先级 |
| 多级反馈队列 | 多个不同优先级、不同时间片的队列，新任务进最高优先级，用完时间片就降级；兼顾短任务的响应和长任务的吞吐 |

**CFS**：每个任务记录**虚拟运行时间**（vruntime = 实际运行时间 × 权重系数，nice 值越低权重越大、vruntime 涨得越慢），用红黑树按 vruntime 排序，每次挑最小的运行。这样每个任务按权重公平地分到 CPU。

## 追问链

- **中断和系统调用的区别？** **中断**是**外部**硬件异步触发的（网卡收到包、时钟、键盘），和当前执行的指令无关，任何时候都可能发生。**异常**是 CPU 执行指令时**同步**产生的（除零、缺页、非法指令）。**系统调用**是程序**主动**执行特殊指令请求内核服务，也叫陷阱（trap），属于同步的。三者最终都是跳到内核里的处理程序，处理完再返回。中断处理分上半部（关中断，快速做最紧急的事，比如把网卡数据拷走）和下半部（软中断、tasklet、工作队列，处理耗时的部分）。
- **原码、反码、补码？** 以 8 位为例。原码：最高位是符号位，其余是绝对值，`-5 = 1000 0101`；有 +0 和 -0 两个零，加减法要单独处理符号。反码：负数在原码基础上除符号位外取反，`-5 = 1111 1010`，仍有两个零。补码：反码 + 1，`-5 = 1111 1011`。计算机用**补码**，因为加法和减法可以用同一套电路（减一个数等于加它的补码），而且只有一个零，所以 8 位能表示 -128 到 127。快速求补码：正数不变，负数是 2⁸ 减去绝对值。Java 的 `Integer.MIN_VALUE` 取反还是自己，就是因为补码范围不对称。
- **什么是上下文切换，什么时候发生？** 时间片用完、更高优先级的任务就绪（抢占）、当前任务阻塞（等 IO、等锁、sleep）、主动让出（`sched_yield`）。用 `vmstat` 的 `cs` 列、`pidstat -w` 看切换次数，切换太频繁说明线程太多或者锁竞争激烈。
- **怎么看一个进程的 CPU 时间花在用户态还是内核态？** `top` 里的 `us`（用户态）和 `sy`（内核态）；`sy` 很高说明系统调用或上下文切换太多。`strace -c -p <pid>` 统计系统调用。
